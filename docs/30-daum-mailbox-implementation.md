# Daum 邮箱实现与验证

日期：2026-10-17。对应需求与决策见 [29-daum-mailbox-plan.md](29-daum-mailbox-plan.md)。基础版已随 `97f4c50` 上线，数据库迁移至 152；本次追加 UI、详情接口和 IPv4 验证修复的发布状态以对应 CI 记录为准。一致性修复及别名收益规则见 [32-daum-parity-fixes.md](32-daum-parity-fixes.md)。

## 已接通的功能

- 管理员 `/admin/daum` 使用现有微软体系的列表、筛选、分页、移动端卡片、详情、导入、维护与批量操作结构。主邮箱和辅助邮箱邮件直接使用微软共享邮件面板；没有新增普通用户资源管理页面。
- 后续 UI 收口直接对照管理员 `ImportMicrosoftModal`：移除 Daum 独有协议选择、导入结果面板和列表批任务进度条。列表只保留七个通用列，Kakao、辅助邮箱与显式别名仅在详情展示；导入成功后刷新并关闭。
- Daum 资源管理及协议位于 `internal/daum`；主资源使用 `email_resources.id`，一个账号下固定维护 `ID@daum.net`、`ID@hanmail.net`、`ID@hanmail2.net` 三个完整地址。
- `daum` 商品接入原 Core、Alloc、Trade、MailMatch、钱包与结算路径。项目商品、订单、工作台、管理统计、系统价格及任务参数已增加 Daum。
- 指定后缀使用 `daum.net`、`hanmail.net`、`hanmail2.net`，随机选择使用 `daum`。随机按有效库存加权，遵守项目后缀屏蔽与 `private_first`；一个批次选定一次后缀，缺货不换后缀。
- 账号根状态、APP 密码、供应范围、完整地址历史和活动占用共同决定库存。同一项目的三个地址可以独立分配，同一地址不能并发重复分配，释放不会删除历史使用事实。
- Daum 使用 256 个分配桶（0–255），按根资源 ID 取模；主地址与两个固定别名共用该账号的桶。桶数量按用户要求独立于微软，候选窗口与重试机制继续共用。
- 显式别名记录及新分配的供货收益快照归平台超级管理员用户 `1`；主邮箱仍使用根账号供应商快照。Microsoft 和 Daum 共用此分配快照规则，旧订单与已结算流水不追溯改写。
- 管理员 API、主 OpenAPI、Go/TypeScript 生成类型、独立公开 API 文档及 AstrBot 的商品类型识别均已更新。

## 导入与凭据

同一个 TXT 批次支持混合三种格式：

```text
邮箱----APP密码
邮箱----登录密码----APP密码
邮箱----登录密码----APP密码----remail取件URL----Kakao账号邮箱
```

解析按 2/3/5 段区分，其他数量返回行级错误。邮箱规范化与密码内容分开处理，保留密码空白、BOM/CRLF 和原始行号。三个同 ID 后缀按同一个账号去重；重复有效账号不覆盖凭据，短格式恢复不清空已有登录密码或辅助资料。

五段格式的辅助地址取自第四段 URL 的 `email` 参数，支持 `/pickup` 与 `/v1/pickup`；第五段独立保存为 `kakaoEmail`，可以与辅助地址不同，例如 Outlook 辅助邮箱与 Kakao 账号。凭据 PUT 仅处理登录密码、APP 密码和收件协议，其他资源字段明确拒绝；辅助绑定和 Kakao 信息通过资源 PATCH 更新，空 Kakao 地址可以清除。

登录密码、APP 密码与导入的 remail 取件链接都只写不回显；列表、详情、任务、失败明细不返回这些敏感值。收件仅使用 APP 密码。导入原件保存在既有私有文件存储，任务只携带资源 ID、凭据修订和执行代次。

导入沿用异步批次、逐行结果、skip/abort、稳定幂等键与中断恢复。管理操作沿用版本校验、幂等回执、审计及根资源锁；替换凭据或停用资源后，旧任务不能覆盖新状态。

## 收件与历史识别

- 真实 IMAP 连接 `imap.daum.net:993`，使用 TLS、APP 密码、只读打开邮箱和 `BODY.PEEK`。
- 真实 POP3 连接 `pop.daum.net:995`，使用 TLS、APP 密码及 `STAT/LIST/UIDL/RETR`，不发送删除命令。
- 解析支持 MIME、多收件人、韩文、文本及 HTML。原邮件的 To/Cc/Bcc 地址保持完整；未知地址不会被填成当前订单地址。
- 实时抓信、抓信锁和缓存按账号协调，读取三个地址的邮件后由 MailMatch 按完整地址隔离。避免只读取一个别名导致其他别名在共用锁下长期拿不到新邮件。
- 实时读取按跨文件夹的接收时间应用总数量上限；遇到已知最新边界停止，不继续向旧邮件回填。共享账号抓取结果由 MailMatch 按实际完整地址隔离。
- 跨 IMAP/POP3 使用 Internet Message-ID 去重；无 Message-ID 时使用规范化原始 MIME 的 SHA-256，保留实际收件协议供诊断。
- 管理员全量抓信在完整读取成功后再进入落库，核对资源、凭据修订和任务代次。读取失败不提交本轮部分邮件，旧任务不能写入。
- 历史识别与微软一样使用 IMAP 的 Inbox/Junk，包括 POP3 配置的账号；仅单一 To 地址形成历史使用证据，三个固定地址分别识别。IMAP 不可用时保留识别未完成状态。

正文与微软共用 MIME 读取代码，优先 HTML，使用相同字符集和附件处理。已删除 Daum 独有的 8 MiB 拒绝条件，并以超过旧上限的邮件验证。实时读取先核对已知最新邮件，按各目录合并后的时间顺序应用总数量上限，不继续向已知边界以前回填；IMAP SORT 和候选选择共用微软实现。

## 网络及故障处理

- 平台 Daum 验证和抓信复用 Microsoft 的 ProxyUseCase，以规范化账号邮箱作为绑定键。按用户后续明确要求，Daum 验证使用 IPv4/Auth，实时抓信和全量历史均使用 IPv4/Fetch；微软原有的历史 IPv6 策略保持不变。资源代理不可用时使用系统备用代理，验证沿用 `max_proxy_attempts`，抓信与微软共用固定三次轮内预算，并避开已失败的代理服务。
- 导入验证只确认 APP 密码认证及收件箱读取能力：IMAP 只读打开 Inbox，非空时读取一封邮件的信封信息；POP3 登录后执行 STAT。不以 Junk 目录或 MIME 内容解析作为首阶段验证条件，成功后才进入独立的历史项目识别。失败诊断仅记录白名单阶段和原因码，不记录账号、代理 URL、密码或底层错误原文。
- Microsoft IMAP 与 Daum 共用 `internal/mailtransport/netdial` 的 HTTP/HTTPS CONNECT、SOCKS5/5h、TLS 连接代码及现有运行时超时设置。使用 Go TLS、最低 TLS 1.2、证书验证、目标主机 SNI，以及对应的 `imap`/`pop3` ALPN。微软网页登录的 HTTP 头、Cookie 和浏览器指纹不用于邮件协议。
- 连接故障反馈代理失败；服务端临时拒绝与账号凭据拒绝不计为代理故障。平台缺少代理时返回可延期状态，不自动绕过代理直连；独立 CMD 可明确选择直连或环境变量代理。
- 去掉了 Daum 独有的跨验证／历史／实时收件账号独占锁和固定 15 分钟外层截止，采用任务领取、共享实时取件租约及可配置历史超时。验证仅在明确新入队且领取证明未变化时进入 validating，重复入队不会覆盖 worker 结果。
- 实时收件与微软共用失败累计：每轮至多三次尝试，三个不可重试失败轮次后才标异常；成功清零，Redis 不能确认计数时不判永久失败。failure_category 只用于诊断，补偿资格依照权威 abnormal 状态。两家共同在事务内核对并锁住资源凭据修订、验证代次及活动分配，再决定退款；恢复或新凭据令旧证明失效。

## 辅助邮箱及已有取件链接

第四段按已有 remail 取件链接解析实际辅助地址，第五段保存独立的 Kakao 账号邮箱。链接仅经内部接口验证，不对导入 URL 发起 HTTP 请求，不修改原邮箱、原订单、原 Token 或原 SMTP 入站归属。

带 URL 的绑定要求链接中的完整地址相符，并且源订单属于 Daum 资源归属用户。支持 Microsoft、域名、Gmail、iCloud、Proto、Daum 的系统内源订单。关联状态与主账号收件健康独立；缺少辅助资料不影响主账号验证，错误链接不能伪装为已关联。

每次辅助邮件列表或正文读取都重新检查：

- Daum 根资源及绑定的当前归属一致。
- 原系统邮箱资源仍有效，源订单仍对应确切辅助地址。
- 源订单及活动分配仍属于对应用户和地址，状态与读取窗口仍允许收件。
- 导入链接中的原 Token 未停用、替换或过期。
- 邮件由 MailMatch 当前归属投影或兼容的订单归属记录判定，必须属于源订单；不能用相同收件地址和时间窗口读取其他项目的邮件。分页支持完整历史列表，正文沿用源订单的取件授权。

没有 URL 的关联要求当前用户拥有对应系统域名。令牌及完整链接不进入 SQL 日志；绑定和读取均支持调用者事务。辅助域名用量统计加入 Daum 关系。
