# Daum 一致性修复与显式别名收益规则

日期：2026-10-17。对应审查清单为 [31-daum-microsoft-parity-review.md](31-daum-microsoft-parity-review.md)。按用户指令修复通用机制差异，并明确将 Microsoft／Daum 的新显式别名收益归超级管理员。基础版 `97f4c50` 已上线，数据库为 152；本文保留各轮验证记录，当前 UI／IPv4 补丁与此前发布区分记录。

## 显式别名收益

- 新分配的 `main` 收益归根资源供应商；新分配的 `alias` 收益归平台超级管理员用户 `1`。
- 修复点在 `internal/alloc/infra/supplier.go`，写入真正决定收益的 `allocation_order_guards.owner_user_id`。Microsoft 与 Daum 使用同一入口，订单供应商、冻结、解冻、结算及退款沿用该快照。
- `internal/billing/infra/repo.go` 的供应商履约统计优先按不可变 guard 归属；仅旧数据的快照为 NULL 时，回退根资源归属，兼容 `00147` 之前的统计。已有非 NULL 快照不受根资源转移影响。
- 旧 guard、订单、钱包和已结算流水不追溯改写；没有财务回填迁移。定价、零金额自有库存及自购防套利规则继续使用公共交易规则。

## 最终审查后的修复

最后一次审查确认的六个缺陷和稀疏库存漏桶问题已修复：

| 问题 | 修复及回归边界 |
|---|---|
| 旧取件请求污染新凭据的失败次数 | Daum Redis 计数键增加凭据修订和验证代次；失败返回后检查当前身份，标异常仍在事务内复查。旧失败只可能计入旧键，旧成功只删除旧键。覆盖更换 APP 密码、同凭据重新验证，以及数据库检查与 Redis 写入之间的交错；新身份第三轮失败才可异常 |
| 主邮箱纠错后历史订单号冲突 | 新历史键使用资源、项目、完整规范化地址的摘要，固定 50 字符；旧后缀键只有完整地址相同才重放。真实 Service/Repo 回归覆盖 main/alias 纠错、新地址幂等和旧事实保留 |
| 主地址能存、自动别名过长 | `CanonicalEmail` 同时校验三个固定地址不超过 255 字符，覆盖导入及纠错入口。skip 报错行后继续，abort 在写资源前拒绝。已受理批次遇明确输入错误或 MySQL 1406 时回滚失败分块、保存安全行号及原因并终止；死锁、断连、未知错误和诊断存储故障仍可恢复 |
| 旧微软履约统计消失 | Microsoft/Daum 使用 `COALESCE(guard.owner_user_id, er.owner_user_id)`，仅 NULL 旧快照回退。验证 NULL、非 NULL 历史归属、平台别名归属和根资源转移；查询不回填财务事实 |
| 同资源改绑辅助邮箱后残留旧邮件 | Daum 辅助面板按资源 ID＋version 重建；覆盖改地址、同地址换授权、换归属、解绑，以及旧列表/正文迟到响应 |
| 批量命令已受理却因进度权限报失败 | 改用 Daum 自有进度接口，不额外依赖治理任务读取权限；查询失败或超时保留原任务 ID 和最后进度。页面回归验证 403/断网后可刷新恢复、变更 POST 仅一次 |
| 256 桶只探测 104 桶而漏掉少量库存 | 默认 4 个单桶后接 100、100、52 桶，每个供货范围最多 7 次候选查询。窗口跨事务重试复用，不重复查桶；真实库存查询遍历全部 256 个哈希起点，单账号均可分配 |

失败轮次阈值、三次协议尝试和一小时 TTL 仍与微软共用。Daum 计数按凭据修订＋验证代次隔离；微软会自动轮换 RT，本轮保留其原有计数键，避免每次自动轮换重置失败预算。旧 Daum 未分代计数键不再读取，等待原 TTL 到期即可。

桶查询复用同一个窗口 helper；Daum 因总共只有 256 桶而覆盖剩余全部桶，Microsoft/iCloud 仍采用原有 100 桶扩展预算。这是针对前期稀疏库存的明确差异。

## 保留并明确说明的差异

- Daum 的 APP 密码、2/3/5 段格式、三个固定完整地址、Kakao 资料和已有取件 URL，均按用户要求保留。没有微软 OAuth/RT、Graph、动态别名创建额度、dot/plus，也没有自动登录 Kakao、远端改绑或找回密码。
- URL 关联仍只能使用源订单授权。源项目不匹配 Kakao 时，邮件即使到达物理收件箱，也不会凭该订单 Token 变成可读邮件。解除关联不改变原邮箱、订单、Token 或 SMTP 入站归属。
- 保留 Daum 已建立的维护运行表、项目历史状态表、命令回执及逐行导入记录。它们保护现有审计和恢复事实，不为表名形式一致而删除数据。
- 短格式恢复保留未提供的登录密码、Kakao 和辅助资料；BOM、UTF-8、控制字符等输入安全检查保留。
- 后端保留精确归属筛选、导入明细／失败 CSV 和批任务查询契约，用于审计与恢复；管理员页面不额外展示这些面板或筛选，使用微软同样的提示、刷新及任务详情交互。
- Microsoft 网页／Graph 的浏览器 profile 与 HTTP 头没有对应 Daum 网页流程。两家的 IMAP 使用共享 TLS／代理代码；POP3、目标域名和协议认证仍需各自适配。
