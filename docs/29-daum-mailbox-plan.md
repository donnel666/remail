# Daum 邮箱实施方案

日期：2026-10-17。状态：方案已实施；代码与验证记录见 [30-daum-mailbox-implementation.md](30-daum-mailbox-implementation.md)。以下保留需求和决策，五段资料含义及辅助读取授权已按实际样本和 review 结论修正。

本方案以管理员微软邮箱的现有页面、导入、资源维护、商品、分配和收件流程为基线。Daum 使用独立业务实现和对应业务表，接入现有平台公共设施。

## 1. 已确认需求

- 新增管理员 `/admin/daum` 页面，以 `AdminMicrosoftEmails.tsx` 和 `admin-microsoft/` 为复制基线，保持表格、筛选、抽屉、导入、维护、批量操作与移动端体验一致。
- 本次资源管理入口在管理员侧；用户购买 Daum 的入口接入现有项目、商品、下单和取件页面。
- 一个 Daum ID 对应一个账号资源、一个收件箱、一个主地址及两个固定显式别名：`ID@daum.net`、`ID@hanmail.net`、`ID@hanmail2.net`。
- 用户已在本次讨论中实测确认 `hanmail2.net` 可以收件，以最后一次实测反馈为准。三个后缀全部进入实现和验收范围。
- 商品分类为 `daum`，展示三个后缀子商品，同时支持指定后缀与随机后缀。
- 收件使用 IMAP/POP3 的 APP 密码；登录密码单独保存，不能替代 APP 密码。
- 完整导入资料包含现有 remail 取件 URL 和 Kakao 账号邮箱。第 4 段 URL 的 `email` 是实际系统辅助邮箱（可以是 Outlook），第 5 段独立保存为 Kakao 账号邮箱。
- 导入支持以下三种格式，允许同一批次混合使用：

| 段数 | 格式 | 解析含义 |
|---|---|---|
| 5 | `邮箱----登录密码----APP密码----remail取件URL----Kakao账号邮箱` | 完整账号、协议凭据、辅助取件与独立 Kakao 信息 |
| 3 | `邮箱----登录密码----APP密码` | 有登录密码与协议凭据，未提供辅助邮箱资料 |
| 2 | `邮箱----APP密码` | 仅提供收件所需协议凭据 |

## 2. 现有实现依据与设计决定

已检查的主要基线：

- 管理页面：`web/src/pages/AdminMicrosoftEmails.tsx`、`web/src/pages/admin-microsoft/`、`web/src/lib/admin-microsoft-api.ts`。
- 资源与导入：`internal/core/app/admin_resource.go`、`internal/core/infra/resource_import_repo.go`、资源验证及导入队列。
- 分配：`internal/alloc/app/allocation.go`、`internal/alloc/infra/repo.go`、`00121` 和 `00122` 迁移。
- 辅助邮箱：`internal/mailtransport/infra/microsoft_binding_repo.go`、`inbound_resolver.go`、`auxiliary_mail_repo.go`、`internal/core/app/admin_domain.go`。
- 独立邮箱类型的已有接入方式：`internal/proto/`、`docs/26-proto-mailbox-implementation.md`。
- 商品模型：`internal/core/domain/project.go`、`project_products` 的 `(project_id, type)` 唯一约束。

**决定 A：独立 Daum 业务，继续使用平台公共入口。** 新建 `internal/daum/{domain,app,infra,api}`；资源、凭据、导入、验证和辅助绑定独立。Trade、Alloc、MailMatch、钱包、权限、审计、文件服务、任务查询继续使用现有模块。代价是新增一种邮箱的明确分支；收益是不用改变成熟微软流程，也不需要先重构一个通用邮箱框架。

**决定 B：保留统一资源 ID。** `email_resources.id` 为根 ID，`daum_resources.id` 与其同主键。三个地址共享同一个根资源，分配事实保存实际交付地址。这样凭据、账号健康、并发抓信和停用可以在账号级统一处理，库存和项目历史仍可按具体地址处理。

**决定 C：子商品沿用微软的“商品类型＋后缀”模型。** 每个项目建立一份 `type=daum` 的商品配置，三个后缀作为下单选择项。继续使用现有价格、供货价、接码/购买开关、服务窗口与质保字段。数据库不为随机选择额外增加第四个商品，也不破坏现有商品唯一约束。三个后缀默认与微软一样共享该分类的价格配置。

约束与迁移要求：

- 主账号按规范化身份去重，不能将三个同 ID 后缀导入成三份账号；业务规范化不改变原始邮件收件地址。
- 别名对资源和地址唯一，分配表约束别名确实属于该资源。账号、两个别名及导入结果在短事务中一致提交。
- 同项目、同具体地址不能重复占用；历史使用约束与当前微软一致，释放不自动抹去已使用事实。跨项目仍执行项目规则。
- 显式别名归平台超管用户 `1`。按用户后续明确的规则，新建 Microsoft／Daum 显式别名分配的供货收益快照也固定归用户 `1`；主邮箱收益归根资源供应商。订单和已结算流水保留原有快照，不能只改别名记录而遗漏收益链。
- 主资源停用/删除/凭据失效时，三个地址统一失去新分配资格；有活动分配时按现有保护规则处理，历史订单地址不能被改写。
- 批量游标和执行租约继续走 Redis/Asynq；不恢复已淘汰的持久批量游标表或 routing candidate 表。
- 使用新增顺序迁移，扩展共享类型、CHECK、外键与索引，验证可重入与旧类型兼容。有业务数据时禁止用 Down 静默删事实。

## 5. 导入及辅助邮箱关联

解析器按 `----` 的字段数量识别 2/3/5 段，其他数量给出行级错误。支持混合格式、BOM、CRLF、空行与稳定原始行号；密码内容不能被随意 trim。分隔符出现在字段中造成歧义时明确拒绝，不能猜字段或静默截断。

- 2 段：第 2 段直接写入 APP 密码；登录密码、辅助关联资料未提供。
- 3 段：第 2 段是登录密码，第 3 段是 APP 密码。
- 5 段：额外解析 remail URL 中的辅助地址与凭据，并独立保存 Kakao 账号邮箱。格式错误按批次 skip/abort 规则处理。
- 新资源缺少登录密码或辅助资料不阻止 IMAP/POP3 验证；详情准确显示“未提供/未关联”。
- 同账号重复导入、已删除资源恢复、跨归属冲突、凭据替换沿用微软行为。短格式缺失字段不视为“清空已有值”，重复导入不隐式覆盖凭据。
- 原始 TXT 留在私有文件存储，导入明细、日志、队列任务和 API 不回传登录密码、APP 密码或含 token 的完整链接。
- 任务只携带资源 ID、代次与凭据修订；旧任务不能覆盖替换凭据、停用、删除后的状态。

辅助邮箱需要落实为可查询的关系：

1. 第 4 段 URL 的 `email` 作为 `binding_address` 的事实来源，解析其对应的现有系统邮箱资源，校验可见性和接收能力。第 5 段是独立的 `kakao_email`，不要求两者相同。
2. 第 4 段接受 remail `/pickup?email=...&token=...` 与 `/v1/pickup?email=...&token=...` 格式，通过内部接口核对邮箱、订单及原 Token；发现指向冲突给出明确结果。它不替代 Daum 的 IMAP/POP3 凭据，也不是新订单的交付链接。导入过程不向任意 URL 发起 HTTP 请求。
3. 辅助关系、主资源与审计在同一个本地事务中写入；系统邮箱尚不存在或不可用时保留输入并显示“未关联/关联异常”，不能伪造关联成功。
4. 关联资料存在、系统能够接收该地址的邮件、上游已经验证该辅助邮箱是不同事实；本地导入不伪造 Kakao 远端验证时间。
5. 带 URL 的辅助邮箱页通过源订单的 MailMatch 归属读取列表及正文；不能只按地址和时间从原始入站箱读取其他项目邮件。只有没有 URL 且当前拥有该域名时才使用精确地址的 `inbound_mails` 查询。关联保留原邮箱、订单及取件链接的归属。
6. 更新辅助域名使用统计，并检查域名停用/删除等现有保护入口。查询、修改和读取正文执行相应辅助邮箱权限，不能仅靠前端隐藏。
7. 辅助邮箱关联异常与主账号收件健康分别展示；已成功的 IMAP 收件结果不能被辅助资料缺失推翻。资源进入可售状态仍需通过既有历史识别等实际资格检查。

本次实现关联与辅助邮件查看。用户已提供完整辅助地址，不需要复制微软掩码推算、网页绑定、找回密码和验证码恢复流程。

## 6. IMAP/POP3 验证与收件

官方协议地址：IMAP `imap.daum.net:993`，POP3 `pop.daum.net:995`，均启用 TLS 和证书校验。Daum 官方说明自 2025-01-02 起协议登录必须使用 APP 密码。

IMAP 为默认协议，POP3 作为可选收件协议；协议选择属于导入批次/资源配置，不增加 TXT 字段。明确的认证失败不能靠盲目切换协议隐藏。

| 项目 | 验收行为 |
|---|---|
| IMAP 验证 | TLS、APP 密码认证、只读打开邮箱、实际邮件查询；存在邮件时验证能够读取，空邮箱查询成功也有效 |
| IMAP 抓信 | 处理 INBOX 和服务端实际提供的垃圾邮箱；使用只读/PEEK，不改已读、不删除 |
| POP3 验证 | TLS、认证、STAT/LIST/UIDL，并在存在邮件时读取验证 |
| POP3 抓信 | 读取并保留服务器邮件，不发 DELE；按 UIDL 避免重复处理 |
| 邮件解析 | 使用已有 MIME 依赖，覆盖中文/韩文、HTML、文本、编码和多收件人 |
| 错误处理 | 区分密码无效、协议未开启、限流、临时网络失败；错误信息脱敏，临时失败按既有队列退避 |
| 历史识别 | 沿用微软验证后识别流程与项目规则；按真实地址记录历史使用，项目变化触发 Daum 独立反扫 |

现有 `go-imap/v2`、`go-message` 等依赖可直接使用。Daum 使用 APP 密码认证，不能直接把微软的 OAuth/XOAUTH2 客户端改域名当成实现。POP3 适配保持小范围，按需要使用标准库协议能力。

POP3 可见邮件范围可能小于 IMAP，尤其是垃圾邮件和其他目录。识别过程只能报告实际扫描范围，不能把“POP3 未发现”当成完整邮箱未使用的证据；需要完整识别的资源保持待完成状态，或使用 IMAP 完成识别。

账号共享收件的关键规则：

- 三个地址共用资源级连接限制和抓信协调，避免并发下单时重复登录同一账号。
- 订单按**完整交付邮箱**匹配收件人，保留 `@daum.net`、`@hanmail.net`、`@hanmail2.net` 的差异；不能把三个地址在邮件匹配时归一为主地址。
- 即使项目启用宽松规则，也不能绕过订单收件地址隔离。收件人不明、多义、仅 Bcc 且缺少可信投递信息时，不把邮件广播给该账号全部订单。
- IMAP 的邮件定位包含资源、文件夹、UIDVALIDITY 和 UID；POP3 使用资源和 UIDL。结合现有邮件去重规则，覆盖重试和切换协议时的重复抓取，确保不重复交付或结算。
- 订单查询、单笔/批量取码、缓存、服务 Token 与管理员收件均加入 Daum 类型及凭据修订检查。

## 7. 商品、库存、随机后缀与交易

| 用户选择 | 请求选择值 | 分配目标 |
|---|---|---|
| `@daum.net` | `daum.net` | 主地址 |
| `@hanmail.net` | `hanmail.net` | 对应固定显式别名 |
| `@hanmail2.net` | `hanmail2.net` | 对应固定显式别名 |
| Daum 随机后缀 | `daum` | 在可售后缀中按可用库存加权选择 |

- 指定后缀缺货必须返回缺货，不能替换成其他后缀。
- 随机选择复用现有加权逻辑，排除零库存、项目禁用后缀、禁用/异常账号、不符合供应范围、已使用或已占用的地址。
- `private_first` 沿用已有自有库存优先语义；批量随机单沿用微软行为，同一批先选定一次后缀，耗尽后不另换后缀。
- 在项目历史、供货及状态均允许时，一个账号最多为该项目贡献三个具体地址；统计必须实时扣除相应地址的历史使用与占用，不能直接用账号总数乘三。
- `mailbox` 只需 `main/alias`；商品复用主邮箱权重路径，dot/plus 权重为零，服务端也拒绝不支持的配置。
- 下单继续进入原 Trade，分配写 `daum_allocations`，订单通过 `order_no` 关联；不在订单表添加 `daum_resource_id`。
- 保留扣款幂等、失败退款、重试恢复、释放、供应商结算、售后、服务窗口、购买激活与质保语义。
- 交付邮箱与系统服务 Token/取件链接；不向买家交付登录密码、APP 密码、导入的现有 remail URL 或 Kakao 辅助邮箱凭据。

| `internal/trade/`、Billing、Aftersale | 报价、订单类型、恢复、Token、结算、退款和售后中的类型分派 |
| `internal/mailmatch/` | Daum 抓信适配、精确收件人、历史识别、邮件缓存及去重、管理员主动抓信、永久失效处理 |
| `internal/mailtransport/` | Daum 辅助关系查询、系统入站关联、正文权限、域名使用统计；核对已有取件 URL 继续可用 |
| `internal/governance/`、IAM | TaskView、批量进度、操作/系统日志、资源与辅助邮箱权限 |
| `internal/platform/`、系统设置 | worker/dispatcher 注册、后台容量、Daum 队列命名与必要参数、价格/供货默认值及倍率 |
| `api/` | 模块装配、管理员路由、公共商品/下单/库存/取件接口、Bot 类型分派、OpenAPI |
| Web | 管理页面、菜单/路由/懒加载、项目管理、商品筛选、工作台、订单/取件、统计与供应商展示、翻译 |
| 生成文件与集成 | `api/openapi.gen.go`、`web/src/lib/openapi/schema.ts`、公开 API 文档及现有集成客户端的类型/选择器 |
| 测试与 fixtures | 新 Daum 样例、资源/订单工厂、共享类型枚举断言、迁移测试、旧邮箱回归 |

管理员接口采用独立 `/v1/admin/daum/resources` 路径，覆盖列表、详情、导入批次/明细、凭据、辅助关系、验证、维护、批量、别名、关联订单和邮件。复用已有权限、CSRF、`Idempotency-Key` 与版本检查，不用宽泛的通配命令路由绕过不同操作权限。

## 9. 实施顺序与完成标准

1. **数据与协议基础**：新建模型和迁移，完成三种格式解析、账号规范化、双密码保管、真实 IMAP/POP3 验证；用受控账号核对三个域名和协议返回的收件地址。
2. **资源、导入与辅助邮箱**：完成异步导入、去重/恢复、状态机、幂等管理命令、固定别名、独立 Kakao 信息、已有 remail 链接关联和辅助邮件查询。
3. **商品与履约**：接入 Daum 商品、三个后缀库存、加权随机、分配、订单、取码、Token、退款/结算及历史识别。
4. **管理员页面与公共展示**：复制管理员微软页面并调整字段/详情；补齐项目配置、工作台、订单、翻译和接口生成文件。
5. **联调与回归**：完成下面的验收矩阵，检查共享路径对现有邮箱类型的影响，再进入迁移和上线准备。

| 验收类别 | 必须通过的场景 |
|---|---|
| 导入 | 三种格式单独/混合；2 段不会当登录密码；4 段及异常字段数拒绝；密码空白保留；BOM/CRLF/空行；原始行号正确 |
| 幂等与恢复 | 同账号跨后缀去重；重复提交；已删除恢复；进程中断续跑；跨归属冲突；短格式不会清空旧资料 |
| 凭据和状态 | APP 密码成功/失败；空收件箱；协议未开；网络超时；换密码后的旧任务失效；禁用/删除不能被后台重新写成正常 |
| 辅助关系 | 系统邮箱正确关联；未找到/指向冲突有明确结果；旧邮件可见；原 remail 取件链接仍有效；越权查询拒绝；辅助异常不覆盖主收件成功 |
| 别名和库存 | 一份账号两条固定别名；三个后缀独立计数；同项目并发抢同地址只成功一次；历史地址不能重新当新库存出售 |
| 随机选择 | 仅选择有效后缀；遵守项目屏蔽和供应范围；按库存加权；指定后缀绝不回退；批量选择行为与微软一致 |
| 邮件隔离 | 分别投递三个地址并通过对应订单取到；同 ID 不同域名不串单；多收件人/Bcc；韩文 MIME；重复抓信不重复交付 |
| 交易 | 扣款、失败退款、幂等恢复、供应商结算、购买激活/质保、释放、Token 与订单隔离 |
| UI/API | 桌面/移动端、列表筛选/分页、导入进度、详情全部标签、错误展示、权限与敏感字段契约、Go/TS/OpenAPI 一致 |
| 数据与回归 | 新数据库与现有库升级；迁移重跑；约束及索引生效；微软、域名、Gmail、iCloud、Proto 相关公共路径回归 |

单元测试聚焦解析、规范化和选择逻辑；数据库测试覆盖事务、并发唯一、恢复与迁移；协议测试覆盖可控成功/失败响应；浏览器验证页面和流程。真实投递验收要与单纯登录/读取旧邮件的验证结果分开记录。

## 10. 资料、边界与当前验证情况

- [Daum 官方：IMAP/POP3 服务器设置](https://cs.daum.net/faq/service/43/category/9234/detail/24081)：IMAP 993、POP3 995、SSL、APP 密码与协议开关。
- [Daum 官方：IMAP/POP3 密码要求](https://cs.daum.net/faq/service/43/category/9234/detail/31143)：自 2025-01-02 起必须使用 APP 密码。
- [Daum 官方：邮箱地址](https://cs.daum.net/faq/service/43/category/18759/detail/38672)：明确列出 `ID@daum.net / ID@hanmail.net`。`hanmail2.net` 的本项目支持依据为用户在本次讨论中的最新实测反馈。

计划阶段仅新增了本方案，未执行迁移或业务测试。后续实现及测试结果见上方实施记录；用户邮箱与生产部署不在本轮验证中。

实现中不复制 OAuth/RT、Graph、微软网页授权、掩码找回、动态别名创建配额和 dot/plus 业务。系统辅助邮箱的本地关联与查看属于本次范围；自动登录 Kakao、修改远端绑定和密码找回不属于当前需求。
