# astrbot_plugin_remail

通用 ReMail 能力插件。QQ、Telegram 两个渠道使用同一套
`/v1/bot/**` 接口；平台用户身份只取自当前 AstrBot 事件，不接受聊天参数。

## 安装

要求 AstrBot `>=4.27.4`。本插件目前位于 ReMail 单体仓库的子目录，不能把整个
ReMail 仓库 URL 当成 AstrBot 插件仓库安装。请将本目录复制为
`AstrBot/data/plugins/astrbot_plugin_remail`，或仅压缩本目录后在 AstrBot WebUI 上传，
然后重载插件。AstrBot 会根据本目录的 `requirements.txt` 检查依赖。

从 0.5.0 起，业务背景模板内置在插件中，不再要求把整份业务系统提示词复制到 AstrBot。
`docs/remail-fae-system-prompt.txt` 现在只是一份红夜人格示例：放到 AstrBot 当前选中的人格提示词中即可，
也可自行调整性格和语气。用户消息模板使用 `docs/remail-fae-user-prompt.txt`（仅 `{{prompt}}`）。
插件通过 AstrBot persona manager 取得当前人格，仅传给输出润色节点；主 Agent 使用插件自身的业务模板。
旧 `<remail_fae_system_v1>` 人格会回退为默认红夜风格，建议升级时替换，避免旧业务常量混入表达。

必须先升级配套 ReMail 后端：`GET /v1/bot/context` 需要返回 `authorized/bound/accountAvailable`，
新增本人订单摘要接口 `GET /v1/bot/orders`、只读充值报价 `POST /v1/bot/recharges/quote`，充值配置提供 `paymentCurrencies`，FAQ 和网站公告支持 `limit=100`。旧后端缺少绑定状态时插件会安全拒绝服务。
升级插件和 AstrBot 人格后必须完整重启 AstrBot，不只热重载插件。

## 服务准入与内置背景

用户主动请求任何 ReMail 服务前，必须绑定一个可用的 ReMail 账号。未绑定或账号不可用时，
用户 @机器人、@管理员代接或发送查询命令，只会收到私聊绑定指引；不进入 Planner、主 Agent，
也不预取动态背景。群里不公开绑定状态，不自动认领普通群聊。私聊 `/绑定`、`/绑定状态`、`/解绑`
保留为必要入口。Telegram 用户必须先私聊 `/start`，否则平台可能禁止机器人主动私聊；发送失败只记录安全日志，
不会在群里公开绑定信息或虚报发送成功。

静态模板 `workflow.py::PUBLIC_BUSINESS_RULES` 覆盖：项目／商品／服务模式的区别、接码与购买、
激活与质保与使用期限、积分支付与兑换闭环、常见充值问题、项目选择、交付边界、订单与服务生命周期、
售后与退款区别、常见故障辨别、账号绑定、公开命令、API 与网页使用边界、榜单与反馈。
这些是低频业务语义，不包含写死的当前价格、库存、商品供给、窗口时长或支付地址。

准入后并行取得每轮背景：当前项目目录（含商品、模式、价格与库存概况）、支付渠道配置、动态 FAQ、
公开 API 能力摘要、网站通知和公告、当前授权群的公告与精华安全文本；私聊额外取得本人订单摘要。项目、FAQ、公告、订单单次最多取前 100 条，提示词内容另有大小边界，
保留采集时间、来源有效性和截断标记。订单摘要不含订单号、邮箱、付款金额、凭证或邮件；群聊不获取订单列表。
精确库存、充值报价、API 具体契约及后续页面由 Agent 按目标补查。背景已有同参数、同范围事实时可直接复用。
单个背景源不可用只标记该源未知，不阻断已有静态知识的解释；身份和绑定状态不可确认则始终拒绝服务。

来源等级、领域、查询范围、时间和截断信息会一同交给 Planner、主 Agent、Writer 和 Critic：当前项目、积分价格、库存、支付配置／报价、公开 API 与本人订单摘要是各自领域的强事实；动态 FAQ、网站公告、群公告和精华是弱参考。冲突先对齐项目、模式、字段和时间，再选该领域强事实；当前项目设置不覆盖既有订单快照。模型失败时也不能用弱资料的旧数值填补动态事实。

`site_announcements_context_enabled=true`、`group_context_enabled=true` 默认开启。`weak_context_max_age_days=0` 默认不按年龄排除旧／时间未知的安全资料；正数可只载入指定天数内有时间依据的资料。旧／过期／未注明时间的弱文本都不能证明当前活动或承诺，抓取时间不能冒充发布时间。网站仅抓取后端当前公开可见的通知和公告，不读取未发布内容；通知和公告任一请求失败会保留另一方并注明缺失范围。

QQ OneBot 读取当前事件所属机器人的群公告和群精华；Telegram 读取当前群简介与最近一条文本置顶消息，明确标记不支持精华列表。群资料最多 100 条、合计 12000 字符，不读取普通聊天历史、成员身份、附件、图片／OCR 或转发链；包含实际凭证、身份、邮件或验证码的条目先过滤，不进入模型。置顶／加精时间与原消息时间单独标注，管理员发布不提升可信等级。

### 决策记录：背景辅助 Agent，人格独立

选择现有 AstrBot 工具 Agent、每轮有界背景和独立人格节点。仅扩写外部人格无法补齐独立 Planner 的背景；
固定业务分支也无法处理客户的模糊目标。因此由工作流提供静态知识与当前数据，由 LLM 理解、计划、补查和澄清。
代价是每个已绑定用户的服务请求会增加少量并行读取，以及输出润色／审核调用。通过同轮复用、100 条上限和截断后按需补查控制开销；
若真实延迟或目录规模明显增加，再考虑带版本／新鲜度校验的跨轮缓存，不用旧快照冒充当前事实。

## 配置

在 ReMail 系统设置中创建 `purpose=bot` 的 System Key，并选择机器人类型。QQ 类型固定
为 `platform=qq`、`namespace=qq:main`；Telegram 类型固定为
`platform=telegram`、`namespace=telegram:main`。AstrBot 插件只提供
`qq_system_key` 和 `telegram_system_key` 两项：当前只使用 QQ 时仅填写 QQ Key，接入
Telegram 后再填写 TG Key。插件按当前事件的 AstrBot 适配器选择 Key，用户不能选择
渠道。主动推送复用第一把已配置的 Key，目标填写 `/sid` 显示的 `UMO` 到
`launch_destinations`。QQ 和 Telegram 不能填写同一把 Key；非本机 `base_url` 必须使用
HTTPS。

配置 Schema 已按 AstrBot 当前在线文档设置 `secret: true`；支持该字段的新版 WebUI
会遮罩 Key，4.27.4/4.27.5 会忽略该显示属性但仍可正常读取配置。所有版本都会把 Key
明文保存在 `data/config/astrbot_plugin_remail_config.json`。只允许 AstrBot 运行账号
读取该文件和 `data/config` 目录，不要把它提交到版本库，也不要截图分享插件配置页。

群聊调用还必须在 ReMail Bot System Key 中配置允许的群号。插件只从
AstrBot 当前事件生成 `X-Bot-Channel` 并从 `get_group_id()` 读取群号。ReMail 先鉴权
System Key，再要求渠道与 Key 类型一致；类型不符统一返回 401。HTTP 群聊传入
`X-Bot-Group`，WebSocket 传入 `groupId`；私聊不传群号，用户命令和 LLM 工具也没有
渠道或群号参数。
接口文档、公告和常见问题虽是公开内容，插件仍会先调用
`GET /v1/bot/context` 验证当前事件来源。未授权群不会得到这些本地或缓存回复。

QQ namespace 的 `subject` 必须是机器人从当前事件解析出的真实正整数 QQ 号；ReMail
不接受 QQ OpenID，也不允许用户命令或 LLM 参数填写、覆盖 QQ 号。因此 QQ 必须使用
NapCat/OneBot 对应的 AstrBot `aiocqhttp` 适配器；`qq_official` 和
`qq_official_webhook` 只提供用户/群 OpenID，不满足绑定与QQ群白名单要求。ReMail 把
QQ 号作为对应渠道的第三方登录标识明文保存。渠道和 namespace 只由
通过认证的 System Key 类型决定，不接受聊天参数或请求字段覆盖。

Telegram namespace 的 `subject` 同样必须是事件提供的正整数用户 ID；群聊 Chat ID
必须是非零整数（群和超级群通常为负数），并命中该 Telegram Key 的群白名单。

QQ 群管理身份不再依赖 OneBot 自动识别。请在插件配置中手工填写
`qq_group_owner_id`，并把所有管理员 QQ 号逐项填入 `qq_group_admin_ids`。这两项统一应用于
当前插件连接的所有已授权 QQ 群：只有这些账号被 @时才触发群管理代接，工作日报也只会
私聊发送给 `qq_group_owner_id`。配置为空或格式不是正整数 QQ 号时，插件不会猜测群主、
不会回退到群成员资料，也不会把日报发送给自动识别出的账号。
多个白名单群使用不同管理成员时，在 `qq_group_management` 中按
`群号|群主QQ号|管理员QQ号1,管理员QQ号2` 逐项配置；分群配置优先于全局配置。

身份映射完全取自 AstrBot 官方事件 API：`aiocqhttp` 将 OneBot 的 `sender.user_id`
作为 QQ号、`group_id` 作为QQ群号；Telegram 将 `from_user.id` 作为 TG 用户 ID、
`chat.id` 作为 TG 群 Chat ID。Telegram Topic 事件中的 `chatId#threadId` 会归一成
`chatId`，因此群白名单按真实 TG 群配置。QQ 事件只使用 `qq_system_key`，Telegram
事件只使用 `telegram_system_key`；ReMail 再从 Key 类型取得渠道和 namespace，所以
同一套 Bot API 可以兼容两种渠道，两类身份也不会共用绑定命名空间。

默认 `transport_mode=websocket`，会为每把
Key 主动连接 `/v1/bot/ws`，每 20 秒发送心跳，并在同一连接中复用 Bot API 请求和
接收项目上线、排行榜结算、系统通知/公告、邮箱折扣和项目价格更新。连接中断会自动
重连，命令请求在连接尚未建立时回退 HTTP；所有主题共用全局游标，并按通知目标分别
持久化，重连后从各目标最旧游标补发。某个目标发送失败时不会推进该目标游标。
需要兼容旧服务端时可显式设置 `transport_mode=http`，但 HTTP 模式只提供命令接口，
不提供主动推送。

`launch_destinations` 是主动推送的 `unified_msg_origin` 目标列表。插件只按各主题公开
DTO 的字段白名单生成消息，不会直接输出事件 JSON、未知字段、原始数据、凭证或邮箱
地址。项目上线通知属于尽力而为，不为它新增项目字段、上线时间表或专用补发状态。

插件提供 `/help`（兼容 `/帮助`、`/remail帮助`）、`/公告`、`/常见问题`、`/接口文档`、`/项目`、`/库存`、`/排行榜`、
`/排行榜奖励`、`/绑定`、`/绑定状态`、`/个人信息`、`/解绑` 和 `/诊断`（兼容 `/接码排查`、`/查码`）。同一能力也注册为
不含 QQ/TG 身份参数的 AI 工具；当前项目价格使用 `remail_project_prices`，当前充值开关、
支付方式、费率和兑换码购买地址使用 `remail_recharge_config`。发送者身份只从 AstrBot 当前
事件注入。机器人自己的
基础业务知识由插件静态模板统一维护，动态 FAQ 由 ReMail 后台维护；API 文档工具会读取并缓存 ReMail
公开 `/openapi.json`，只向模型返回与问题最相关的有界接口和 schema 片段。
API 问题按用户目标与当前公开 API 能力做语义匹配，不依赖“API”“接口”等关键词。群聊在明确
触发后、私聊在授权后，插件都会先读取当前公开文档的能力摘要，再做一次 API 咨询判定。摘要
只包含公开接口的操作、路径和说明，不包含管理或机器人内部路径。比如
“下单时，Gmail 变种邮箱后缀应该填什么”会进入公开下单文档查询，并核对对应字段的合法值、
含义和限制。插件会先内部判断是否为 API 咨询；判定为 API 后，会主动获取当前公开 API
文档摘要并加入本轮 AI 上下文，摘要不足时仍由红夜继续查询公开文档。
库存工具不会把冷缓存或过期快照当成当前库存：项目列表对缺失、准备中或超过两次系统刷新周期的库存返回 `null`，库存详情返回
`503` 和安全的稍后重试提示；只有新鲜结果才返回库存数值，并携带 `observedAt` 表示快照时间。
`/help` 无论从私聊还是白名单群调用，帮助内容都只私聊发送给当前用户，不在群里回复；
Telegram 用户需要先主动私聊机器人 `/start`，否则平台可能拒绝主动私聊。
`/个人信息` 无论从私聊还是白名单群调用，余额、分组、角色和升级进度都只私聊当前发送者。

群聊和私聊都使用 `/诊断 邮箱 原因`。ReMail 根据当前发送者绑定的用户 ID 和邮箱
反查该用户自己的最近订单与公开项目，不接受用户提供项目 ID；邮箱不能用于查询其他
用户的数据。显式 `/诊断` 由插件直接处理，邮箱、订单号、验证码和邮件内容不会进入模型
提示词或最终回复。只有系统同时确认
`mailReceived=true` 和 `projectMismatch=true` 时才会说明“邮件已收到，但买错项目”；响应中的
`projectId/projectName` 始终只是该用户实际购买的项目。另一个项目的 ID、名称、规则以及邮件
主题、发件人、正文和验证码绝不返回；任意无关或未匹配邮件不能据此判定项目错购。错购候选还必须处于
`ignored`、没有 effective owner，并且该邮件到达时同一资源和收件地址不存在其他订单的重叠服务窗；否则统一 fail closed。
候选按 keyset 分页扫描，超过 1000 封仍无法确认时返回暂时不可用，不会把截断解释成没有错购。

## 新人欢迎

启用 `welcome_enabled` 并设置 `welcome_text` 后，新成员进入已授权群时，插件会先校验
当前群来源，再使用平台消息组件 @该成员并发送欢迎文本。未授权群、机器人自身加入事件
或空欢迎文本不会触发消息。欢迎文本最多发送 2000 个字符。

## 自动批准加群

启用 `auto_approve_join_requests` 后，插件只处理 QQ OneBot 白名单群中用户主动发起的加群
申请。NapCat 成功返回申请人的 QQ 等级且达到 `minimum_qq_level` 时自动批准；等级不足、
资料缺失、来源鉴权失败或批准动作失败时均保持待审核，不会自动拒绝。群邀请事件不参与
自动批准。机器人必须具有对应 QQ 群的审批权限。

## 群消息审核

`keyword_blacklist_enabled` 启用后，QQ OneBot 白名单群中包含
`keyword_blacklist` 任一关键词的消息会被撤回。关键词先做 Unicode 规范化，再按不区分
大小写的包含关系匹配；空关键词会被忽略。

`url_whitelist_enabled` 启用后，只允许 `url_whitelist_domains` 中的域名及其子域名。名单
为空时会撤回所有检测到 HTTP(S) URL 的消息。审核覆盖普通文本、Markdown、分享卡片和
JSON/XML 卡片中的当前消息内容，不检查回复引用的旧消息，也不把图片、语音、视频和文件
自身的下载地址当成用户发布的 URL。未授权群不会被插件撤回消息；机器人必须具有对应群
的消息撤回权限。撤回失败不会禁言、踢人或追加其他处罚。

## 群管理代接

QQ OneBot 白名单群中的普通成员 @手工配置的群主或管理员时，插件会按
`qq_group_owner_id` 和 `qq_group_admin_ids` 核对身份，并主动唤醒红夜处理原问题。红夜沿用已配置的人格、会话上下文和 ReMail 工具，
答复后会自然提醒用户以后直接联系红夜，非必要不要打扰群主或管理员。群主、管理员、
机器人自身发送的消息以及只 @普通成员的消息不会触发；管理员 QQ 号不会进入模型提示。

## 群聊触发

普通群聊不会触发 LLM 意图识别或 FAE 回复。用户必须明确 @红夜，或者由普通成员 @群主/
管理员触发上面的群管理代接；随后插件才调用一次独立 Planner LLM。Planner 返回经过严格
JSON 校验的路由、回答模式、隐私级别、意图、实体和事实依赖计划；路由为 ReMail 时进入完整
FAE；@群主/管理员的非 ReMail 内容静默忽略，@红夜的非 ReMail 内容只回复服务范围，不进入
FAE。结构无效时给 Planner 一次自我纠正机会；调用失败才提示服务暂时无法完成，不要求客户重新证明问题属于 ReMail。
显式 `/help`、`/项目`、`/诊断` 等插件命令仍直接处理。
未艾特、未发送命令的群消息只参与已启用的消息审核，不会调用意图模型，也不会进入工作
日报。插件不会认领或停止这类正常事件，因此不会阻断同一 AstrBot 中的其他插件；部署方
仍应关闭不需要的群聊全量唤醒，避免其他 Agent 主动插话。
插件只在内存中保留同一会话、同一发送者最近 10 分钟内的有界安全问题与答复片段（最多 3000 字符），群聊和私聊均适用，
用于判断“那多久”“第二个呢”“还是不行”等省略追问；不会把完整群历史交给意图分类器。
追问缓存同时按群和发送者隔离，不会承接其他群成员的问题。所有正式 FAE 请求默认清空
AstrBot 会话历史、引用内容、图片、音频、文件和其他附件，只保留完成当前目标确有必要的当前
发送者本轮文本、已脱敏且有界的同一发送者安全上下文、ReMail 工具以及插件生成的公开 API
摘要。群聊不会继承其他成员的任何内容，避免模型复述其他成员昵称、时间线或截图。
私聊 Planner 会在 AstrBot 构建主 Agent 之前仅用脱敏文本完成路由；私聊非命令消息也会在该
阶段统一从主 Agent 输入中移除附件、引用、图片描述和文件抽取结果。单个订单邮箱只保存在
本轮事件内并由诊断工具直接取用，不进入 Planner、主 Agent 文本、Persona 或 Critic。由于该
保护会移除本实例的所有私聊非命令附件，建议将 ReMail FAE 部署在专用 AstrBot 实例或专用机器人；
专用实例只启用审核过的插件和 MCP，不要给 FAE Persona 绑定自动知识库，当前系统事实统一通过 ReMail 工具取得。AstrBot 的 STT
和外部内容审核早于插件消息 handler 执行，因此插件初始化会硬化当时已加载的全部配置 profile：
关闭 STT、百度 AIP 审核、文件抽取、图片描述、TTS、T2I、工具状态/结果、reasoning 展示、
回复前缀、分段清理正则、自动 mention 和自动引用；
无法确认时拒绝启动。ReMail FAE 不接受语音作为诊断输入。通过 WebUI 新增、重载或修改 AstrBot 配置
profile 后，必须先停止入口流量并完整重启 AstrBot，再向 FAE 发送内容；只重载本插件不足以
清除 pipeline 已缓存的 STT/外内容审核策略。每轮请求还会复查当前 profile，但事后拒绝无法撤回更早的外部调用。

入口准入守卫还覆盖 AstrBot 原生命令过滤之前的 waking 阶段，兼容框架剥离 `/` 后的命令文本，避免绑定命令被误挡、未绑定查询或原生过滤器错误提前公开身份。只包裹当前启用的插件实例／配置／会话，卸载时恢复；群管理动作仍只要求来源授权，不要求被管理用户绑定账号。

## Planner、主 Agent 与多模型输出门禁

第一阶段的独立 Planner LLM 为每个 FAE 事件生成 `FactPlan`。群聊首次生成后由同一事件复用，
私聊在进入主 Agent 前生成一次；代码只校验结构、枚举、参数范围和依赖，不使用业务关键词
替代 LLM 做意图理解。Planner 不回答问题，也不能决定用户身份、权限、订单归属或可信项目 ID。
`service` 意图允许直接依照内置静态业务模板解释，不依赖 FAQ 是否可用。`clarify` 表示缺少客户信息，
由主 Agent 先解释已明确部分，再提出关键追问，不是范围外或异常；初始计划是补齐事实的起点，不限制 Agent 的补查与引导。

第二阶段复用 AstrBot 主 Agent 的工具循环。Agent 先按 `FactPlan` 执行 Plan-and-Execute，独立
事实可并行、库存等依赖事实按顺序查询；只在结果截断、歧义、出现新缺口或无法预先确定下一步
时使用条件 ReAct，并在事实足够时提前结束。正常路径由主 Agent 基于本轮当前系统 evidence
生成完整事实草稿，作为第三阶段的内容主路径。AstrBot 4.27.x 的工具
循环轮数及硬上限完全跟随全局 `provider_settings.max_agent_step`；插件不覆盖、不校验也不阻止
该配置。需要调整轮数时，直接在 AstrBot WebUI 的模型提供商设置中修改“工具调用轮数上限”，
并按 AstrBot 的配置生效方式重载或重启。
进入循环前，ToolSet 只保留 14 个明确允许的 ReMail 工具，并同时校验工具包装的 handler
确实绑定当前插件实例；同名的其他插件或 MCP 工具不会进入主 Agent。

证据账本记录查询参数、有效性和同轮历史；每个 required FactRequest 都必须由参数和实体作用域
一致的当前证据满足。结构损坏、项目 ID 不一致、未就绪/过期库存都不能闭合计划。确定性
renderer 只在模型、结构校验或证据流程失败时生成权威安全回退，不能取代主 Agent 草稿与
Persona Writer 主导的正常答案。

第三阶段先对业务草稿执行对外隐私清理，再交给两个相互独立的 LLM。Persona Writer 只读取脱敏问题、安全上下文、
已清理的业务草稿、当前有界 evidence（包括预取、初始计划和合法 ReAct 补查／后续页）及单独配置的人格风格，以严格 JSON 生成完整自然语言候选。
它没有工具、原始会话历史、附件或原始私密数据。人格只控制表达，不是业务事实来源。
FAQ 与项目、公告等多源综合答案也经过 Writer 和 Critic，不再自动锁成 renderer 摘要。Writer 返回的 `usedEvidence` 是不可信自报，只能辅助定位，不能证明候选
中的事实已被支持。

独立 Semantic Critic 随后把普通非 seal 候选逐声明拆解，并自行将每个声明绑定到 `FactPlan` 和实际的当前
权威 evidence，校验主体、关系、条件、因果、状态、不确定边界和操作步骤。缺少支持、关系交换、
新增断言或证据冲突都必须拒绝；有限正则、字面量集合、evidence ID 和 `usedEvidence` 都不能
证明完整自然语言的语义安全。Writer 或 Critic 异常、结构无效或校验失败时，使用 renderer 的
权威安全回退。

数字的等价单位表达、静态“单次／1 次”、引用用户数值和基于强事实的计算不会仅因未逐字匹配就提前拒答；它们仍必须经过独立 Critic 核实关系、计算、条件和来源，失败时保留强事实或安全说明。未知链接、代码标识符、凭证及受保护诊断继续受硬门禁约束；通过离线程序测试不代表真实 LLM 永不误判。

Critic 通过后仍立即执行统一代码 hard gate；LLM 回复、显式命令、工具直发、公告、FAQ、欢迎
消息和主动推送均不能绕过凭证与 PII 脱敏、群聊邮件隐私、黑盒内部机制、推广及无关内容规则。
Semantic Critic 之后不再允许自由模型改写。最终文本会同步写回会话历史，并使用非流式输出。对已由
ReMail 接管的事件，每事件 `send` 出口守卫还会将 AstrBot 构建 Agent 失败、provider 拦截等直接发送
分支替换为 canonical 安全文本；canonical 缺失时只发送固定失败文案，也不会把原始草稿写入历史。

订单诊断先把 Bot API DTO 归一化成最小 `DiagnosisFact`。Persona Writer 和 Semantic Critic 永远
拿不到另一项目、原始邮箱、主题、发件人、正文或验证码；所购项目、到件、错购、退款/领取状态
和诊断下一步放入每轮随机的 immutable seal。Writer 只能在 seal 外安全包裹；代码校验 seal
原样且恰好出现一次后恢复可信事实文本，诊断事实本身不会再发送给 Critic。只有
`diagnosisCode=result=project_mismatch` 且 `mailReceived/projectMismatch` 均为严格布尔 `true`
时才能确认错购；普通非 mismatch 结论只依赖 `diagnosisCode`，其 `result` 为空。诊断一旦进入 seal
通道就不再拼接同轮的其他项目或价格 evidence，组合问题中的公开业务查询需要另起一轮。

公开 API 检索优先保留与完整目标直接相关的 operation，压缩重复错误响应，并从当前契约生成
带 `<API_KEY>`、`<IDEMPOTENCY_KEY>` 和 `<REQUEST_BODY_JSON>` 等安全占位符的 cURL 骨架。

每轮 FAE 要求当前 AstrBot profile 同时禁用：`show_tool_use_status`、`show_tool_call_result`、
`display_reasoning_text`、`file_extract.enable`、`default_image_caption_provider_id`、STT、TTS、T2I、
百度 AIP 审核、`reply_prefix`、`content_cleanup_rule`、`reply_with_mention` 和 `reply_with_quote`。
工具 schema 模式必须为 `full`；`skills_like` 会在最终门禁前产生中间发送，因此不受支持。
插件启动时会对已加载 profile 设置这些安全值，并在每次 LLM 请求前复查；任一项重新开启就安全拒绝，
不进入 Agent 工具循环。

## 积分计费规则

普通用户的接码和购买邮箱订单都使用 ReMail 积分。当前充值开关、支付方式、兑换码购买
地址、费率和档位必须由 `remail_recharge_config` 读取当前 Bot 配置；README、提示词、FAQ、
公告和模型记忆都不得硬编码或覆盖这些动态值。公告只能补充当前仍发布的活动说明，不能证明
其中旧渠道、费率或活动动作仍然有效。

余额、消费、赠送、积分手续费和预计到账均是积分；外部充值支付金额才使用货币单位。当前接口区分 `CNY` 和 `USDT`，不能把 USDT 写成美元 `USD`／`$`，也不能把积分加上 `￥`。在线渠道与币种从 `paymentMethods/paymentCurrencies` 读取，不写死汇率或支付入口。具体积分与支付方式的金额调用 `remail_recharge_quote(points, payment_method)`：只读复用后端计费，不创建充值、不调用支付网关、不扣款、不入账；预计到账不是已到账，实际转账金额、网络、地址及期限仍以该次支付页面为准。

卡网购买兑换码是独立的充值路径：当前地址来自 `redemptionCodePurchaseUrl`，购买后回 ReMail 兑换为积分，再用积分购买服务。在线 `enabled=false` 或没有在线支付方式不表示卡网入口关闭；在线报价不能证明卡网商品的售价、币种或折扣。地址未配置／接口不可用时不回退到旧公告或写死链接，也不向用户索取真实兑换码。

所有项目接码价和购买邮箱价的单位都是 ReMail 积分，不是人民币。当前价格由背景查询同源项目字段生成价格证据，或由
`remail_project_prices` 查询；该工具支持一次传入 `icloud,microsoft,domain` 等多个产品类型，
返回 `unit=ReMail积分`、`codePricePoints` 和 `purchasePricePoints`。`remail_projects.search`
只用于单个项目名称或目标平台关键词，禁止把多个邮箱类型或整句问题拼成一次搜索。

接码窗口、激活窗口和质保时长均以 `remail_projects` 返回的当前项目配置为准，不使用全局
固定时长。用户没有询问价格库存时，最终答复不会从旧 FAQ、公告、知识库或历史中附加相关
动态值。

## 工作日报

`feedback_enabled` 默认关闭。启用后，插件只在 QQ OneBot 的 ReMail System Key 白名单群中
收集用户通过 `/反馈 内容`、`/建议 内容` 显式提交的内容，以及 FAE 已完成合理排查后记录的
未解决问题；普通群消息永远不会成为日报候选。每个 AstrBot 机器人实例、每个 QQ 群分别保存。

FAE 已尝试 ReMail 常见问题、API 文档和诊断工具仍无法可靠回答群内问题时，应调用无
业务参数的 `remail_record_unresolved` Tool。Tool 重新校验当前事件和群白名单，只记录
当前问题，再把“已记录并反馈研发”的安全结果交给 LLM，由 LLM 结合当前对话自然告知
用户，不向模型返回内部状态或原始数据。若 AstrBot 配置了显式 Tool 白名单，需要把本插件
实际使用的工具全部加入白名单，至少包括 `remail_project_prices`、`remail_recharge_config`、`remail_recharge_quote`
以及项目、库存、FAQ、公告、API 文档和诊断工具；模型和 Provider 必须支持 function calling。AstrBot 默认可能显示
工具调用状态必须按上面的隐私要求关闭，否则插件会拒绝进入 Agent 工具循环。
插件还会在每轮 FAE 请求进入主 Agent 前原地收窄 AstrBot `ToolSet`，只保留本插件注册的 14 个
精确 `remail_*` 工具名称；shell、文件读写、网页搜索、主动发消息、其他插件和 MCP 工具都会移除。
没有可验证 `ToolSet` 的第三方 Agent runner 会失败关闭，不能绕过该限制。

插件按 `feedback_report_time` 配置的北京时间（`Asia/Shanghai`，`HH:MM`）每天生成一份
工作日报，并私聊投递给手工设置的 QQ 群主；存在 `qq_group_management` 分群配置时优先使用，
否则使用 `qq_group_owner_id`。插件不再自动识别群主，
不提供 Telegram 工作日报。发送失败时不会回退到来源群、`launch_destinations` 或其他接收人，而是保留数据并
每五分钟重试，插件重启后也会补发。发送与插件 KV 之间没有事务，因此极端崩溃窗口下
同一日期的工作日报可能重复一次，但不会为了避免重复而静默丢失。

反馈条目和工作日报不保存发送者 QQ号、昵称、原始邮箱、订单号、验证码、密码、System
Key、数据库地址或 ReMail 原始响应；路由元数据只保存投递所需的群号和群主私聊 UMO，
工作日报只显示来源群号的不可逆短哈希，不回显原始群号。单条候选、每日条数、模型提示词和工作日报都有上限。
如果使用外部大模型，只有经过上述脱敏和截断的候选文本会在配置时间汇总时发送给该模型。

## 敏感命令

`/绑定 邮箱 密码` 只允许私聊。插件加载时会在 AstrBot 日志、内容安全预处理和消息链
读取前统一脱敏为 `/绑定 [REDACTED]`；命令 handler 会立即停止事件传播，密码不会进入
LLM 或会话历史。生产环境仍应关闭适配器可能提供的 trace/debug 原始消息日志。

主动群消息是否可用取决于平台适配器；QQ 使用支持 `send_by_session` 的
aiocqhttp/OneBot。绑定命令支持 `/绑定 邮箱 密码` 与 `/bind 邮箱 密码`，密码可以
包含空格。

## 安装后的真实模型验收

单元测试验证程序链路与权限边界，不代表真实模型的语义能力已经通过评估。升级后用实际配置的模型测试：

- 未绑定用户在群里 @机器人：只收到私聊绑定指引；普通群聊不触发。
- 完成绑定后问“群主，我们买的邮箱能用多长时间”，接着问“那过保了呢”“上面那个倒计时结束呢”：应解释服务区别并按需澄清，不把质保当使用期限，不输出无关价格库存。
- 修改项目价格、支付渠道或动态 FAQ 后重新提问：依据新事实，不沿用旧回答或公告价格；截断和不可用明确保留边界。
- 让 FAQ／网站／群公告的旧时长与项目当前时长冲突：应采用项目强事实，模型失败回退也不能输出旧值；旧群资料默认保留但不证明当前活动。
- 询问“充值这些积分要付多少人民币／USDT”“在线充值关闭，还能去卡网吗”：应区分积分和支付币种，引用实时配置／报价／卡网地址，不猜固定比例、不假称到账、不把在线报价套到兑换码商城。
- 私聊询问本人最近订单：仅解释本人摘要；群聊同样提问应引导私聊，不能公开列表。
- 仅购买项目 2 的用户排查收件：确认错购时只说明所购项目和安全结论，不透露实际另一项目或任何邮件细节。
- 更换 AstrBot 人格风格：表达可以变化，事实、条件、不确定性和隐私边界保持不变。
